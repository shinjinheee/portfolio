Background

PD·FE와의 합의 부재로 반복되는 스타일 값 전달 비용 제거

Grid·Spacing·Font·Effect·Border Radius를 Design Token으로 정의하고 Figma Variables로 관리했으며, 구축된 구조를 기반으로 Component·Color 정의를 design.md 명세로 정리해 개발에 전달했어요.

  • 스타일 기준 일원화

    Grid·Spacing·Font 등을 Design Token으로 정의하고
    Figma Variables로 관리해
    디자인·개발이 동일한 기준을 참조하는 단일 구조를 수립

  • 반복 소통 비용 제거

    토큰 기반 참조 구조로 매번 수동 전달하던
    스타일 값 커뮤니케이션을 대체하고
    PD·FE 간 불필요한 소통을 최소화

  • Design.md 명세 생성

    구축된 Design Token과 Component·Color 정의를
    design.md 명세로 정리해
    개발이 그대로 참조·구현하도록 전달

Result

기준이 만든 변화

공통 기준이 생기자 디자이너와 개발자의 작업 방식이 달라졌어요.

  • PD디자인 할 때 컬러를 외울 필요가 없어졌어요 🥹
  • PD디자인 QA건 수가 현저히 줄어들었어요!
  • FE컬러가 토큰으로 묶여있어 호출·적용하기 편해요
  • FEdesign.md 명세로 정리돼 있어 컴포넌트 작업이 수월해졌어요

1~2회40%

Painpoint

단순한 UI 작업에도
소모되는 디자이너 리소스

단순한 UI 상태값도 FE와의 합의 부재로 매번 전달해야 했고,
그 과정에서 발생하는 비용이 소모적이라고 느꼈어요.

Opportunity

전달 방식이 아니라,
전달하지 않아도 되는 구조의 부재

반복되는 수치 재확인은 소통 문제가 아니었어요.
공유 가능한 기준 자체가 없었고, 토큰 구조로 기준을 만들면 이 반복을 없앨 수 있다고 판단했어요.

네이밍 규칙 없음 · 용도 불명확
