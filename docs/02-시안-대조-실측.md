### ⚠️ 오렌지 미검출

설계서 §3은 오렌지를 "페이지당 1회만 쓰는 유일한 포인트"로 규정했지만,
**시안 전체에서 `#FF812E` 계열이 한 번도 나오지 않는다.** 푸터도 파랑 단색이다.

세 가지 중 하나다:

1. 시안 작업 중 오렌지를 뺐다 → 설계서 §3, §4-6에서 오렌지 항목 삭제
2. 아직 안 넣었다 → 시안에 반영 후 재측정
3. 다른 페이지(case-*)에만 쓸 계획이다 → 설계서에 적용 범위 명시

**결정 필요.** `tokens.css`에는 토큰만 남겨두고 아무 데도 쓰지 않은 상태다.

실측된 조합은 총 9종. `Eyebrow`(Space Grotesk 14px / 대문자 / 자간 0.08em)는
**시안에 아직 없다** — 설계서 §4-3의 계획 단계 값이므로 그대로 유지했다.

### 반응형 처리

실측값은 1920px 기준이다. Display 100px을 고정하면 1440px에서 깨진다.
`tokens.css`는 `clamp()`로 처리했다.

```css
--fs-display: clamp(48px, 5.2vw, 100px);
```

1920px에서 정확히 100px, 1024px에서 53px로 떨어진다.
설계서 §10의 "1440px 이상에서 완성도 우선" 방침과 맞다.

## 3. 구조 차이 (중요)

여기가 가장 크게 갈린다. **설계서의 index 구성과 시안이 서로 다른 페이지다.**

| 섹션 | 설계서 §5 | 시안 실측 | 상태 |
|---|---|---|---|
| Hero | 3D 유리 오브젝트 + 헤드라인 2줄 + 버튼 2개 | **없음.** Selected Work부터 시작 | 🔴 충돌 |
| Selected work | 2×2 그리드, 카드당 6칼럼 | **가로형 리스트 4행** (좌 이미지 / 우 텍스트) | 🔴 충돌 |
| Also worked on | 4분할 아코디언 (근거 4건) | **없음** | 🔴 누락 |
| 스테이트먼트 | 설계서에 없음 | **`Before I draw a screen / I find where the flow breaks`** | 🟡 시안에만 |
| Archive | 배너 + 마퀴 → 별도 페이지 | 2행 마퀴 14장 (`View All` 링크 있음) | 🟢 대체로 일치 |
| About 진입 | 축약 섹션 + 버튼 | **없음** | 🔴 누락 |
| Footer | 파랑 + `Work With ME` + 오렌지 원형 버튼 | 파랑 + `Work with me` + `Back to the Top` | 🟡 오렌지 없음 |

### GNB

```
설계서:  [SHINJINHEE]   Work  Archive  About        [Let's contact us →]
시안:    [SHINJINHEE]   Work  Archive  About  Contact   [포트폴리오 다운로드 ↓]
```

시안은 Contact가 **메뉴 항목**이고, 우측 버튼은 **PDF 다운로드**다.
설계서는 Contact가 버튼이다. 시안 쪽이 제출 요건(PDF 접근성)에 더 맞아 보인다.

### 판단

시안은 **홈의 일부만 그려진 상태**로 보인다. Hero와 About 진입이 통째로 없고,
설계서에만 있는 `Also worked on`(근거 4건 아코디언)도 미반영이다.

**둘 중 하나를 정해야 한다:**

- **A. 설계서 우선** — 시안을 설계서 구성에 맞춰 보강. Hero·Also worked on·About 진입 추가
- **B. 시안 우선** — 설계서 §5를 시안 구성으로 수정. Hero 없이 Selected Work로 바로 시작

A를 권한다. Hero가 없으면 첫 화면에서 "누가 무엇을 하는 사람인지"가 안 잡히고,
설계서 §5-1이 지적한 3D 오브젝트의 역할(그래픽·컬러 감각 증명)도 사라진다.
참여도 요건과 직접 닿는 `Also worked on`도 빠질 수 없다.
