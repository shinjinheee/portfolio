### 자간 (letterSpacing)

TEXT 노드 35개 전수 조사 결과, 자간이 걸린 것은 **7개뿐**이고 값은 세 종류다.

| 값 | 개수 | 대상 |
|---|---|---|
| `-4.000px` | 6 | Space Grotesk w600 **100px** 대형 헤딩 |
| `-1.920px` | 1 | Space Grotesk w600 **48px** (`Detail`) |
| `0.000` | 28 | **그 외 전부** |

100px→`-4.0` 과 48px→`-1.92` 는 둘 다 정확히 **`-0.04em`** 이다.
Figma 가 tracking 을 `-4%` 로 저장한 것을 API 가 px 로 환산해 내보낸 형태다.

설계서에는 `-0.02em` 으로 적혀 있었고 이는 실측의 **절반**이다.
그 값으로는 `Selected Work` 가 671.7px 이 되어 실측 648px 보다 3.7% 넓어진다.

**Pretendard(한글) 계열은 전부 0** 이고, Space Grotesk 라도 소형(nav 18px, 푸터 16px)은 0 이다.
`--ls-tight` 를 본문·제목 계열로 확장하면 안 된다.

> `--ls-eyebrow: 0.08em` 은 실측 근거가 없다. JSON 전체에 **양수 letterSpacing 이 0건**이다.
> 설계서 §4-3 의 자체 판단값이며 시안에 `.eyebrow` 사용처도 아직 없다.

폰트 메트릭(`SpaceGrotesk-SemiBold.woff2` hmtx + GPOS kern 68,866쌍)으로 역산 검증했고
`-0.04em` 만 5개 텍스트 전부에서 오차 1px 이내로 일치했다.

### 반응형 처리

실측값은 1920px 기준이다. Display 100px을 고정하면 1440px에서 깨진다.
`tokens.css`는 `clamp()`로 처리했다.

```css
--fs-display: clamp(48px, 5.2vw, 100px);
```

1920px에서 정확히 100px, 1024px에서 53px로 떨어진다.
설계서 §10의 "1440px 이상에서 완성도 우선" 방침과 맞다.

### GNB

```
설계서:  [SHINJINHEE]   Work  Archive  About        [Let's contact us →]
시안:    [SHINJINHEE]   Work  Archive  About  Contact   [포트폴리오 다운로드 ↓]
```

시안은 Contact가 **메뉴 항목**이고, 우측 버튼은 **PDF 다운로드**다.
설계서는 Contact가 버튼이다. 시안 쪽이 제출 요건(PDF 접근성)에 더 맞아 보인다.

### 판단

시안은 **홈의 일부만 그려진 상태**로 보인다. Hero와 About 진입이 통째로 없고,
설계서에만 있는 `Also worked on`(근거 4건 아코디언)도 미반영이다.

**둘 중 하나를 정해야 한다:**

- **A. 설계서 우선** — 시안을 설계서 구성에 맞춰 보강. Hero·Also worked on·About 진입 추가
- **B. 시안 우선** — 설계서 §5를 시안 구성으로 수정. Hero 없이 Selected Work로 바로 시작

A를 권한다. Hero가 없으면 첫 화면에서 "누가 무엇을 하는 사람인지"가 안 잡히고,
설계서 §5-1이 지적한 3D 오브젝트의 역할(그래픽·컬러 감각 증명)도 사라진다.
참여도 요건과 직접 닿는 `Also worked on`도 빠질 수 없다.

## 3-1. 헤더 · 푸터 세부 실측

### 로고

`logo 2` = **173 × 24.15**. (이전 버전 `logo 1` 은 192.8 × 24.1 이었다.)

내보낸 SVG 는 `height="25" viewBox="0 0 173 25"` 인데 이는 Figma 익스포터의 **올림 아티팩트**다.
SVG 안의 `<clipPath><rect width="173" height="24.15">` 가 실제 경계를 그대로 갖고 있고,
패스 좌표를 3중(제어점 상한 / 베지어 극점 해석해 / 6.7만점 샘플링)으로 계산한 결과도
정확히 `x [0..171]`, `y [0..24.15]` 였다. 여백은 **전부 하단 0.85px**.

→ `height` 와 `viewBox` 만 `24.15` 로 고쳤다. **왜곡 0%, 잘림 0px.**

> 함정: `viewBox` 를 그대로 두고 `height` 만 24.15 로 바꾸면
> `preserveAspectRatio` 기본값 때문에 로고가 3.4% 축소되고 좌우에 공백이 생긴다.
> `preserveAspectRatio="none"` 은 3.4% 세로 압축 왜곡을 만든다.

### 헤더 버튼

**173 × 42**, padding `8 20`, gap 4, radius 8, fill `#343843`,
글자 **Pretendard w500 14px / lh 26**.

시안은 Hug(내용 기반)지만 값이 정확히 173 이다.
브라우저 폰트 렌더링으로는 172.32 가 나오므로 `.btn--w173` 으로 고정했다.

### Back to the Top 탭 — 겹침 8px

**떠 있는 것이 아니라 파란 박스 위에 8px 겹쳐 있다.**

```
tab.bottom (3927) - box.top (3919)  = +8.00px   겹침
tab.right        - box.right        =  0.00px   우측 flush
box.top          - tab.top          = +49.00px  박스 위 노출 높이
```

탭 SVG 의 **평평한 밑변은 local y=49.31**(절대 3919.31 ≒ 박스 윗변 3919)이고,
그 아래 7.69px 은 우측 14.68px 구간에서만 아래로 휘는 **오목 필렛**이다.
이 필렛이 박스 안으로 파고들어 두 도형을 하나로 잇는다.

증거 두 가지:
- `Frame 18` 의 `rectangleCornerRadii = [20, 0, 20, 20]` — **우상단만 radius 0**
- 탭과 박스의 오른쪽 변이 완전 일치 (차이 0.00px)

`bottom: 100%` 로 붙이면 필렛 7.69px 이 허공에 떠서 탭이 분리돼 보인다.
→ `bottom: calc(100% - 8px)`. 겹침 비율은 탭 높이의 **13.49%** 이므로 반응형에서도 비례시킨다.

> `.site-footer__box` 에 `overflow: hidden` 을 넣으면 겹친 8px 이 잘려 다시 떠 보인다. 넣지 말 것.

라벨은 **정중앙** 정렬이다 (Figma 라벨 중심 182.5 ≒ 탭 중심 182).
`padding-left` 나 `translateY` 보정은 불필요하다.

### 푸터 탭이 차지하는 자리

탭은 `position: absolute` 라 레이아웃 높이를 차지하지 않는다.
그래서 앞 섹션과의 간격을 200+200 으로 잡으면 **탭이 49px 위로 당겨진다**.

```
실측: 본문 끝 2432 → 탭 2832 (400)  → 박스 2881 (449)
```

`.site-footer` 상단 패딩에 탭 돌출분(`높이 − 겹침 = 49`)을 더해야 맞는다.
반응형에서 탭 높이가 바뀌므로 변수는 `.site-footer` 에 두고 `.to-top` 이 상속받는다.

### 함정 두 가지

**1) 칩 테두리를 `border` 로 그리면 안 된다.**
1행 칩 합계가 1323 이고 컬럼이 1334 라 여유가 11px 뿐이다.
`border` 는 칩마다 2px 씩 더해 12개면 24px 초과 → 한 줄이 두 줄로 접힌다.
`box-shadow: inset 0 0 0 1px` 로 그리면 레이아웃 크기가 변하지 않는다.

**2) 보조 버튼은 글자와 아이콘 색이 다르다.**
글자 `#626262`, 아이콘 stroke `#ADADAD`. `currentColor` 하나로 묶으면 어긋난다.
