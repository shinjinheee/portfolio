문제 정의

운영자가 시스템을 직접 제어할 수 없는 구조가 문제

크롤링과 데이터 갱신 프로세스가 개발팀 중심으로 운영되어 운영자는 직접 제어할 수 없었어요. Airflow DAG를 몰라도 Admin UI에서 설정과 실행이 가능하도록 재설계했어요.

누적된 기능 관련 VOC

  • “매번 개발팀에 요청해야 해 번거로워요”
  • “바로 크롤링을 실행하고 싶어요”
  • “최신 데이터가 며칠씩 걸려요”
  • “대상 추가마다 티켓이 필요해요”
  • “진행 상황을 확인할 수 없어요”

문제 정의

  • 데이터 수집 프로세스가 개발팀 중심으로 설계
  • 운영자가 크롤링·갱신을 제어할 수 없음
  • 데이터 신선도 관리가 어려운 구조

솔루션

  • Airflow를 Admin UX로 추상화
  • UI에서 대상·주기·실행을 직접 제어
  • 조회 도구에서 운영 도구로 확장

문제 정의

Airflow DAG를 몰라도 크롤링 대상을 직접 등록

대상·스케줄·수집 항목을 폼에서 입력하면, 시스템이 DAG를 자동 생성해요.

개발팀 요청 의존

“개발 요청이 필요해요” “DAG가 뭔지 모르는데...” “며칠씩 기다려요”

크롤링 요청은 계속되지만 바로 대응할 수 없는 상태

1
크롤링 대상 등록 폼 대상·스케줄·수집 입력 및 선택
2
크롤링 시작 등록 즉시 자동 시작

문제 해결

운영 도구로 확장하면, 운영자는 개발팀 없이 데이터를 직접 통제

운영자가 부담 없이 따라갈 수 있도록 등록 흐름을 3단계로 나눴어요

크롤링 상태 확인

  • 크롤링 전

  • 크롤링 중

  • 실행 정보 확인

    운영자가 개발팀 도움 없이 상태를 직접 확인

문제 해결

운영자가 크롤링 상태를 실시간으로 직접 확인

등록 전 진행 중•완료까지 각 시점의 상태를 한 화면에서 직접 확인할 수 있도록 Back Office에 운영자 도구를 추가했어요.

  • STEP 1

    대상 설정

    URL을 입력하면 사이트 정보를 자동으로 가져와요

  • STEP 2

    스케줄 설정

    매일·매주·매월 중 골라 한 줄로 주기를 설정해요

  • STEP 3

    수집 설정

    필요한 항목만 골라 처리 시간을 줄여요
